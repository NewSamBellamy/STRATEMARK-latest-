# Audit — 2026-07-29

Evidence-based audit run before any further code changes, prompted by the founder's note that
there's "a gap between what you're saying is done and what's actually done." Every number below is
measured, not estimated. Data source: `apps/web/src/sample/frontier-snapshot.json` — the real output
of a live keyed research run on the Frontier AI market (20 companies, 24 cards, 100 metrics).

---

## 1. Provenance: the trust hole is real

| Measure | Result |
|---|---|
| Total metrics | 100 |
| verified | 29 |
| estimated | 32 (32/32 carry a "how we got this" method note ✅) |
| unknown | 38 (rendered as honest gaps ✅) |
| user_verified | 1 |
| **verified metrics with NO source at all** | **3 of 29 (10.3%)** ❌ |
| verified metrics with a URL source | 26 of 29 |

**Finding 1.1 — "Verified" can exist with zero evidence.** Nothing in the schema or code prevents
it. Three figures are labelled verified with no citation whatsoever:

- `OpenAI / Safety / Governance Controversy Entity` — valuation = $852B
- `OpenAI / Safety / Governance Controversy Entity` — arr = $25B
- `OpenAI / Safety / Governance Controversy Entity` — users = 900M

**Finding 1.2 — that company name is itself a data-modelling bug.** A Vice (controversy) card
created a pseudo-company and inherited OpenAI's metrics, un-sourced, as "verified". Vice cards
should not mint companies or duplicate metrics.

**Finding 1.3 — every stored source URL is an opaque Google redirect.** All 26 are
`vertexaisearch.cloud.google.com/grounding-api-redirect/...`. They *do* resolve to real
publishers — verified by following them:

- → `openai.com/about/` (HTTP 403 at the target; bot protection)
- → `futuresearch.ai/anthropic-financial-forecast/` (HTTP 200)

But the user sees a meaningless Google hostname, not the publisher. Two consequences: they cannot
judge the source, and these grounding redirects are known to be **temporary**, so "verified" links
will rot over time.

**Finding 1.4 — we already have the publisher name and throw it away.** The grounding response
includes a `title` per citation, which holds the publisher domain. Reports keep it; metrics
discard it, storing only the URL. Observed titles from one report: `bingx.com`, `youtube.com`,
`gmicloud.ai`, `carnegieendowment.org`, `cnas.org`.

**Finding 1.5 — source quality varies enormously and is currently invisible.** A figure sourced to
`carnegieendowment.org` and one sourced to a YouTube video or a crypto exchange's blog
(`bingx.com`) are presented identically as "verified". For a product people make financial
decisions on, the publisher must be visible and ideally weighted.

## 2. Performance: the app is not slow, but the deck grid is chatty

| Measure | Result |
|---|---|
| Single-file demo load event | **343 ms** |
| Shell painted ("Your decks") | **451 ms** |
| Deck grid ready after click (24 cards) | **1,075 ms** |
| **External logo requests on deck open** | **66** ❌ |
| Other external requests | 1 |

**Finding 2.1 — the HTML file is the complete application, not a reduced build.** Same bundle, same
code. It boots in ~340 ms. The only difference is that without a key it runs on seeded sample data.

**Finding 2.2 — 66 network requests for 24 cards is the real cause of the sluggish feel.** The logo
resolver probes up to three sources *per card, at render time*, sequentially. That produces
staggered image pop-in and layout churn, and is vulnerable to third-party rate limiting.

## 3. Logos: a trusted source exists and it is better than what we use

Tested Wikidata's logo property (P154) → Wikimedia Commons for the companies that previously
rendered as blurry 32 px favicons:

| Company | Result |
|---|---|
| Anthropic | `Anthropic logo.svg` — **vector SVG**, HTTP 200 |
| Palantir Technologies | `Palantir Technologies logo.svg` — **vector SVG**, HTTP 200 |
| Databricks | `Databricks Logo.png` — 27.9 KB PNG, HTTP 200 |
| Mistral AI | logo exists; request returned **HTTP 429** (Commons rate limiting) |
| Together AI | **no P154 property** — genuine gap |

**Finding 3.1 — vector logos solve sharpness completely.** SVG scales to any size with no blur,
which removes the entire upscale-vs-postage-stamp tradeoff we've been managing.

**Finding 3.2 — coverage is good but not total**, so the existing icon chain must remain as
fallback, with the lettermark plate as the final honest ending.

**Finding 3.3 — Commons rate-limits rapid sequential requests (observed 429).** Combined with
Finding 2.2, this points to one architectural fix: **resolve each logo once during research and
store it on the company record**, never at render time.

## What this audit changes about the plan

1. **Provenance is the top priority** and it is a schema problem, not a UI problem. Metrics need a
   list of citations (publisher + url), the publisher must be displayed, and "verified" must be
   *impossible* without at least one citation — enforced in code and covered by a test.
2. **Resolving logos at research time fixes three findings at once** (1.x sharpness, 2.2 chattiness,
   3.3 rate limiting).
3. **Vice cards must stop minting pseudo-companies** and must never inherit metrics.
4. Redirect URLs should be resolved to their final publisher URL at research time where possible, so
   citations survive the grounding links expiring.

## Honest limitations of this audit

- It analyses one live run (Frontier AI, 20 companies). Accuracy characteristics may differ by
  market, especially for smaller/private companies.
- I did not hand-verify each figure against its cited page: one sampled target returned HTTP 403
  (bot protection), so automated claim-checking is unreliable. The structural findings above are
  what can be established rigorously, and they are the ones that matter most.

# Addendum — free-tier throughput (live measurement, 2026-07-29)

Goal set by the founder: **3–5 decks per day on a free key**. Measured against a real 9-company
deck run (market: Non-Alcoholic Spirits, US).

## Documented free-tier limits (verified via search, 2026-07)

| Limit | Value |
|---|---|
| Requests/minute — flash line | **15 RPM** |
| Requests/minute — flash-lite | **30 RPM** |
| Requests/day | **1,500 RPD** |

The binding constraint is **per-minute**, not per-day. That reframed the problem: daily volume was
never going to stop us; *bursting* was.

> Note: one search result claimed Search grounding is paid-tier only. Our own evidence contradicts
> it — every run in this project has used grounded search on a free key successfully. Trusting the
> measurement over the claim.

## Measured

| Measure | Result |
|---|---|
| Duration (9 companies) | 223 s |
| Total API calls | **41** (20 grounded, 21 structure) |
| Peak requests in any 60 s window | 18 across two models (grounded stayed under its own 12 cap) |
| Rate-limit failures | **0** |
| Metrics produced | 88 — 22 verified, 15 estimated, 51 unknown |
| **verified figures carrying a citation** | **22 / 22 (100%)** ← was 26/29, with 3 unsourced |
| Decks/day at the 1,500 cap | **36** |

**Finding A.1 — the 3–5 decks/day goal is met with enormous headroom.** ~41 calls/deck implies ~36
decks/day against the documented cap. Daily quota was never the risk.

**Finding A.2 — provenance enforcement works on live data.** Every verified figure in this run
carries a real citation. The audit's 10.3% unsourced-verified rate is now 0%.

**Finding A.3 — discovery over-returns and we were paying for it.** 20 grounded calls for a
9-company deck implies ~17 candidates enriched against a target of 8. Each extra candidate is a
grounded call. Now capped to the target, company cards kept first.

## Changes made for throughput

1. **Proactive per-model rate limiting** (sliding window: 12 RPM grounded, 24 structure). We pace
   before sending instead of absorbing 429s and sitting in backoff — the difference between "rate
   limited right away" and a run that simply works.
2. **Batched tier review**: one cohort-wide call instead of one per company (−9 calls on a
   10-company deck). It also *improves* ranking quality, because the model compares companies
   against each other rather than judging each in isolation — which is what makes T1-vs-T8
   defensible.
3. **Candidate cap** to the requested target (Finding A.3).
4. **Local usage meter** — counts requests per day in the browser and reports remaining headroom in
   decks, so quota stops being invisible.
