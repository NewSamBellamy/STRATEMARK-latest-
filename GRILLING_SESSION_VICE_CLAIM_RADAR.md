## Summary

The Vice-Claim Alert Radar is the surviving feature from STRATEMARK Sentinel after two roast panels killed the battle simulator, provenance layer, and auto-tier evaluation. This grilling session stress-tested the remaining plan and resolved 10 critical decisions.

**Core Decision:** Hosted service (not local daemon), next-morning latency (4-6 hour batch window), free scraping infrastructure, email alerts only (Slack later), per-company pricing.

## Questions & Answers

### Q1: Who pulls the data from sources?

**Answer:** I will host the service. Next-morning latency is acceptable.

**Recommendation:** ✅ Confirmed. A hosted batch service is the right architecture for a solo founder. It separates the scraping burden from the user's machine and allows you to control data quality.

---

### Q2: How do you reconcile "I host the service" with "customers won't trust a cloud backend with classified data"?

**Answer:** The data being scraped is *public* (SEC filings, court records, news). It's not the customer's private data — it's the competitor's public footprint. The customer's private data (their card decks, their internal notes) stays local. You're only syncing *public intelligence*, not *private strategy*.

**Recommendation:** ✅ This framing holds. The value proposition is: "We monitor the public footprint of your competitors so you don't have to." The customer's private analysis stays in STRATEMARK. The public intelligence flows to them via email.

---

### Q3: What's the scraping infrastructure?

**Answer:** Free sources only. No paid alternatives.

**Recommendation:**
- **EDGAR:** Free RSS feed + EDGAR Full-Text Search API (free, no key required). Latency: same-day.
- **Google News:** RSS feeds per company (free, structured). Skip the paid API.
- **PACER:** RECAP Archive (free, crowd-sourced federal court filings) via courtlistener.com API. Skip paid PACER access.
- **State regulators:** Don't build 50 scrapers. Use Google News RSS filtered by state + regulator name. Coverage: ~80% of material actions. Accept the gap.
- **RSS/company blogs:** Standard RSS parsing. Free.

**Total infrastructure cost:** ~$0/mo for data sources. Cost is compute (small VPS running daily cron) + time maintaining scrapers (~2-4 hours/month).

---

### Q4: How does the user receive alerts?

**Answer:** Email digest (daily), Slack later.

**Recommendation:**
- **v1:** Email digest only. Universal, no integration required. Works for PMM/CI owners who don't live in Slack.
- **v2:** Add Slack webhook for power users.
- **v3:** In-app notification via STRATEMARK desktop sync.

**Email delivery:** SendGrid or Resend free tier (100 emails/day free). Scales to ~$20/mo at 1,000 users.

**Why email first:**
- No integration required
- Universal (everyone has email)
- Tests demand without building Slack integration
- Users don't need STRATEMARK open to receive alerts

### Q5: What does the alert actually say?

**Answer:** 4-6 hour batch window. Optional real-time for user-specified events.

**Recommended alert format:**
```
Subject: [COMPETITOR] Change Detected — [DATE]

Company: Acme Corp
Change Type: Regulatory Action
Source: State AG Press Release (Texas)
Confidence: reported-secondary
Source URL: https://texasattorneygeneral.gov/...

Summary: Texas AG filed consumer protection complaint against Acme Corp 
regarding billing practices. Case #2026-CV-1234.

---
Generated by STRATEMARK Sentinel on 2026-07-31
View in STRATEMARK: [deep link to card]
```

**Key design decisions:**
- **One change per email.** Don't batch multiple changes — users scan subject lines.
- **Confidence label in every alert.** `sourced-primary` / `reported-secondary` / `unknown`.
- **Deep link to STRATEMARK card.** Email is the hook; desktop app is where they manage intel.

---

### Q6: How does the user configure real-time vs batch?

**Answer:** Default batched (4-6 hour window). User can toggle real-time for specific event types per company.

**Recommended preference model:**
```
Default: All changes → batched (4-6 hour window)

Real-time triggers (user toggles per company):
  ☑ Vice claims (regulatory, lawsuits) → real-time
  ☑ Funding rounds → real-time
  ☐ Hiring changes → batched
  ☐ Pricing changes → batched
  ☐ Landing page updates → batched
```

**Why this split:**
- Vice claims and funding are time-sensitive — PMM/CI owners need to know *today*.
- Hiring, pricing, landing pages are signals, not events. Batched is fine.
- Default to batched to control email volume and costs.

**Implementation:** Store preferences in Postgres (row per user per company). Daily cron checks preference before deciding batch vs real-time queue.

### Q7: What happens when a scraper breaks?

**Answer:** Graceful degradation with user transparency.

**Recommended degradation model:**
1. **Per-source health checks.** Each source has a `last_success` timestamp. If >24 hours stale, mark `degraded`.
2. **Don't silent-fail.** If a source is down, next alert includes: `⚠️ Google News was unavailable during this scan. Results may be incomplete.`
3. **User can see source status.** In STRATEMARK desktop app: "All sources healthy" or "2 sources degraded (Google News, RSS)".
4. **Your monitoring.** UptimeRobot or similar (free tier). You get alerted before users notice.

**Cost:** $0/mo for monitoring. ~2-4 hours/month maintaining scrapers.

### Q8: What's the MVP scope?

**Answer:** Thinnest vertical slice that delivers value. 2-week build.

**v1 scope (ships in 2 weeks):**
- [ ] Hosted scraping service: EDGAR RSS + RECAP + Google News RSS + company blogs
- [ ] Daily batch job: scrape → diff → generate alerts
- [ ] Email alerts: batched 4-6 hour window, one change per email, source URLs, confidence labels
- [ ] User onboarding: sign up → add companies → configure preferences → receive alerts
- [ ] Stripe checkout: $40-60/mo, 5 tracked companies included

**v1 does NOT include:**
- Real-time alerts (v2)
- Slack integration (v3)
- Battle simulator (killed)
- Provenance layer (killed)
- Auto-tier evaluation (killed)
- STRATEMARK desktop app integration (v2 — sync alerts to local SQLite)

**Why this scope:**
- 2-week build for solo founder
- Tests core hypothesis: "Will PMM/CI owners pay for automated competitor change alerts?"
- No desktop app dependency — web service + email
- First dollar in 2 weeks

### Q9: What's the onboarding flow?

**Answer:** 3-step funnel, free trial, no credit card.

**Recommended onboarding:**
```
Step 1: Sign up (email + password, or GitHub OAuth)
  → Free trial: 14 days, 3 companies tracked

Step 2: Add companies
  → Search by name or URL
  → Auto-detect EDGAR CIK, news sources, RSS feeds
  → Show preview: "We'll track 4 sources for Acme Corp"

Step 3: Configure alerts
  → Default: all changes batched
  → Toggle: vice claims → real-time (optional)
  → Add Slack webhook (v2, hidden in v1)

→ Done. First alert arrives within 24 hours.
```

**Key design decisions:**
- **Free trial, no credit card.** Reduces friction. Validates with real usage.
- **3 companies in trial.** Enough to see value, not enough to replace a paid tool.
- **Auto-detect sources.** User types "Acme Corp" → you find EDGAR CIK, news, RSS automatically.
- **First alert within 24 hours.** Immediate gratification.

### Q10: What's the pricing model?

**Answer:** Per-company pricing, not per-seat.

**Recommended pricing tiers:**

| Tier | Price | What You Get |
|------|-------|--------------|
| **Trial** | $0 | 3 companies, 14 days, batched alerts only |
| **Pro** | $49/mo | 5 companies, batched + real-time vice claims, email alerts |
| **Team** | $99/mo | 15 companies, all features, 3 team members |
| **Enterprise** | $249/mo | 50 companies, Slack integration, priority support |

**Why per-company, not per-seat:**
- PMM/CI owners track companies, not seats. Willingness-to-pay scales with competitor count.
- Solo PMM tracking 3 competitors pays less than corp-dev team tracking 15.
- Per-seat punishes collaboration. Per-company rewards growth.

**Revenue projection:**
- 50 Pro users × $49/mo = $2,450/mo
- 10 Team users × $99/mo = $990/mo
- **Total at 60 users: $3,440/mo (~$41K/yr)**

Viable solo-founder business. No VC needed.
